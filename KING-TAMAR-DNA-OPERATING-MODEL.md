# KING TAMAR / PRIME DNA OPERATING MODEL

## System Status
GitHub is connected as the operating layer for the PRIME / King Tamar production system.
The project uses a production-line methodology, not a random tool warehouse.

Core principle:
Do not build a warehouse of tools. Build a production line.

## Active Production Line
User request -> DNA extraction -> prompt enhancement -> prompt compression -> output generation -> QA evaluation -> final deliverable.

## Connected Tool Logic

### Prompt Booster Layer
Purpose: Turn raw user requests into precise, premium, execution-ready prompts.
Use when: The user asks for images, slides, copy, investor decks, webinar scripts, visual corrections, or marketing assets.

### TokenSaver / Prompt Compression Layer
Purpose: Compress long instructions into short operational prompts without losing brand DNA.
Use when: A prompt is too long, repetitive, or overloaded.

### Promptfoo / Evaluation Layer
Purpose: Evaluate prompt/output quality against PRIME / King Tamar standards.
Use when: Comparing prompt variants, checking slide quality, checking text hierarchy, validating image generation rules.

### ComfyUI / Image Workflow Layer
Purpose: Support external image-production workflows, especially if creating repeated visual assets at scale.
Use when: The workflow requires systematic image generation beyond one-off ChatGPT image creation.

### PPT / Slide Generator Layer
Purpose: Convert research, copy and visual prompts into investor-grade presentation structures.
Use when: Building decks, speaker notes, teaser decks, webinar decks, FAQ decks, or sales decks.

## Content Rules

Never invent numbers.
Never promise guaranteed returns.
Never use language such as:
- guaranteed
- risk free
- safe money
- guaranteed yield

Always separate:
- verified data
- developer/market claim
- analytical inference

## Slide / Image QA Checklist

A deliverable is approved only if:
1. Hebrew text is sharp.
2. RTL is correct.
3. Visual hierarchy is clear within 3 seconds.
4. PRIME color system is respected.
5. The slide feels premium, not generic.
6. The output serves an investor decision.
7. No faces or source photos are distorted.
8. No unverified claims are added.
9. The message is clear and defensible.
10. The output fits 16:9 presentation use unless requested otherwise.

## Default Output Model

For any user request, first decide which production line applies:

1. Image Production Line
Raw request -> visual DNA -> prompt booster -> compression -> generate/edit -> QA.

2. Investor Deck Line
Raw content -> source audit -> narrative architecture -> slide structure -> copy -> speaker notes -> QA.

3. Research Line
Question -> source hierarchy -> verified/claim/inference split -> insight -> chart/table recommendation.

4. Sales Enablement Line
Audience -> pain point -> core message -> script -> objections -> CTA.

5. Content Marketing Line
Topic -> thesis -> proof -> investor framing -> compliance-safe copy -> CTA.
