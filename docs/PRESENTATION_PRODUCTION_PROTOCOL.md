# PRIME / King Tamar Presentation Production Protocol

## Purpose
This protocol turns every presentation tool into a controlled production system for PRIME / King Tamar.

The goal is not to generate random slides.
The goal is to create investor-grade decision assets that move the client from understanding to trust, product desire, Excel validation, apartment selection and intelligent reservation.

## Core Principle
Every slide is not a design task.
Every slide is a stage in the investor decision process.

## Production Sequence
Every presentation task must follow:

```text
source -> narrative role -> screen copy -> visual system -> QA -> final deliverable
```

Expanded production line:

```text
request -> source/DNA extraction -> prompt refinement -> prompt compression -> output generation -> QA evaluation -> final deliverable
```

## Source-of-Truth Lock
The following layers must remain separate:

1. `King_Tamar_Client_Copy_V6.md` — controls client-facing screen copy only.
2. `King_Tamar_Sales_Playbook_V6.md` — controls internal salesperson guidance only.
3. `PRIME_Visual_DNA.md` — controls visual language, colors, typography and RTL.
4. `source-log.md` — controls verified facts, assumptions and data requiring verification.

If old prompts, old slide text or previous outputs conflict with the V6 source files, the V6 source files win.

Every King Tamar slide must be mapped to the approved 16-slide flow before editing or generation:

1. King Tamar: מגדל פרימיום בלב טביליסי
2. סיפור השקעה שמתחיל במקום הנכון
3. טביליסי: עיר שמתקדמת קדימה
4. עיר בצמיחה, כתובת במרכז העניינים
5. Archi: היזם שמוביל את הבנייה
6. מני בניש: החיבור הישראלי לגאורגיה
7. PRIME: הדרך הישראלית להיכנס נכון
8. גב חזק מאחורי החלטה גדולה
9. בין כיכר הגיבורים לגשר קינג תמר
10. 15 Merab Aleksidze: כתובת שקל לזכור
11. מורשת של מלכות בלב טביליסי
12. ריזורט אורבני בלב טביליסי

15. King Tamar במספרים ברורים
16. מהסיפור לבחירת הדירה שלך

If a slide does not belong in the main 16-slide flow, classify it as:
- appendix
- sales-support slide
- source-verification slide
- Excel-transition asset
- marketing/banner asset
- internal-only training asset

## Two-Headline System
For every slide, first provide exactly two headline options:

1. `סיפורי־יוקרתי` — elegant, premium, story-led, emotionally clear.
2. `ברור־מכירתי` — direct, simple, value-led, clear in 3 seconds.

Then choose one recommended client-facing headline.

## Screen Copy Framework
Every client-facing slide should normally include:

```text
Recommended headline
Short subtitle
3–4 concise cards
Optional message line only if it adds real value
IMAGE_EDIT_PROMPT
Data requiring verification
```

Do not place internal explanations, objections, psychology, salesperson scripts or source-validation notes on the client screen.

## Writing Standard
Use Hebrew that is:
- simple
- modern
- premium
- classic
- clear to Israeli investors
- client-facing
- sales-oriented with value
- understood within 3 seconds

Avoid:
- פוזיציה
- סקייל
- סטייל
- מיקרו־לוקיישן
- מערכת החלטה
- over-consulting terminology
- research-style headlines
- negative headline openings such as לא עוד / לא רק / לא מתחילים

## Visual Standard
All visual outputs must follow:
- 16:9 unless otherwise requested
- full Hebrew RTL
- right alignment
- Heebo-style typography
- PRIME colors only
- Light and Dark variants for strategic slides
- no smeared text
- no broken Hebrew
- no generic Canva look
- no loud blue
- Champagne only as subtle accent
- no face alteration for real people

Official colors:
- PRIME Navy `#0F1E3A`
- Deep Blue `#2F63C8`
- CTA Blue `#4D8DF7`
- White `#FFFFFF`
- Cloud `#FAFAFB`
- Mist Gray `#F3F4F6`
- Graphite `#111827`
- Steel Gray `#6B7280`
- Champagne Sand `#D6C7A1`

## Dual Colorway Rule
For every strategic slide:

1. Build the layout once.
2. Confirm message and hierarchy.
3. Create Light version.
4. Duplicate the exact structure.
5. Create Dark version.
6. Run RTL and typography QA on both.

The structure, hierarchy and content must remain identical. Only color and atmosphere change.

## Commercial Safety Rule
Never invent data.
Never use guaranteed-return language.
Never claim certainty of appreciation, safety or demand.

Forbidden:
- תשואה מובטחת
- עליית ערך ודאית
- ללא סיכון
- רווח בטוח
- כסף קל
- PRIME מבטיחה תשואה

Preferred:
- צפי
- פוטנציאל
- תרחיש עבודה
- לפי חומרי הפרויקט
- בכפוף לבדיקה
- דורש אימות
- בדיקה באקסל לפי יחידה

Every numeric, financial, regulatory or commercial claim must have a source before client use. If no source exists, mark `דורש אימות`.

## QA Gate
Before delivery, every output must pass:

- Is the source layer correct?
- Is it Client Copy or Sales Playbook?
- Is Hebrew RTL correct?
- Is the headline clear in 3 seconds?
- Are all claims sourced or marked `דורש אימות`?
- Is there any guaranteed-return language?
- Does the slide advance the client toward Excel, apartment selection or reservation?
- Does it look like PRIME / King Tamar, not Canva?
- Is it immediately usable?

## Final Rule
The guide explains.
The slide sells the idea.
The Excel validates the decision.
The closing turns the decision into action.
