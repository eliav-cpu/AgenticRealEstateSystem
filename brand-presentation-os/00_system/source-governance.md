# PRIME Source Governance

Status: Working
Owner: PRIME Invest
Purpose: Control what can be used as source material for client-facing outputs

## Core principle

No client-facing financial, legal, operational or investment claim should be created without a visible source basis.

## Source classes

### 1. Source of Truth

Use for:

- signed project documents
- official developer materials
- final approved price lists
- final contracts
- approved financial models
- approved brand guide

Usage level:

Can support client-facing materials, subject to context and review.

### 2. Approved Template

Use for:

- approved copy blocks
- approved FAQ answers
- approved sales scripts
- approved slide structures
- approved email templates

Usage level:

Can be reused, but must be checked against the specific project context.

### 3. Working Draft

Use for:

- early outlines
- internal notes
- rough copy
- unreviewed slide drafts
- working research

Usage level:

Internal only until reviewed.

### 4. Project Material

Use for:

- brochures
- presentations from developers
- project one-pagers
- marketing PDFs
- images and renderings

Usage level:

Can inform narrative, but claims must be checked and labeled.

### 5. External Research

Use for:

- market reports
- public data
- official statistics
- public articles
- competitor/benchmark data

Usage level:

Useful for context. Must be dated, sourced and checked for relevance.

### 6. Client Output

Use for:

- sent decks
- sent emails
- sent proposals
- signed-off documents

Usage level:

Reference for consistency, but do not treat as source unless its claims are backed.

### 7. Archive

Use for:

- outdated versions
- superseded decks
- rejected copy
- old assumptions

Usage level:

Do not use directly.

## Required source-log fields

Every project should maintain a source-log with:

- source name
- file type
- owner
- date received
- status
- reliability
- key facts extracted
- risks / caveats
- client-use status
- next action

## Claim review levels

### Low risk

Examples:

- brand language
- general process copy
- soft CTA
- meeting framing

Review required:

Brand voice only.

### Medium risk

Examples:

- project specifications
- amenities
- location claims
- developer background
- benchmark framing

Review required:

Source check + brand voice.

### High risk

Examples:

- ROI
- rent assumptions
- yield
- appreciation
- legal structure
- tax claims
- guarantees
- banking / finance claims

Review required:

Source check + legal/financial review + brand voice.

## Forbidden without review

Do not use as fact without review:

- guaranteed return
- no risk
- safe investment
- full security
- certain appreciation
- all buyers
- market will definitely rise
- fixed demand
- protected capital

## Final output classification

Every deliverable should be marked as:

- Draft
- Working
- Review
- Approved
- Client Ready
- Archive

## Final rule

The system should prefer an honest missing-data note over an unsupported confident claim.
